# Pi Chat Web 三方向设计规范

## 产品与目标

Pi Chat Web 是一个运行在本机可信环境中的 Agent 工作台，不是普通客服聊天框。它把持续对话、文件读写、Shell 命令、编辑补丁、运行状态、Steer/Follow-up 队列、上下文压缩、模型与 thinking 切换、会话恢复和分支放在同一条工作流里。此次方向探索的目标不是给现有页面换一套颜色，而是找到一种能同时支撑「向别人演示 Pi 如何工作」和「开发者自己长时间使用」的信息架构。三版必须使用同一批真实内容与功能，只改变构图、视觉语法和控制层级，保证用户能基于真实界面而不是风格名做选择。

## 目标受众与场景

主要受众是理解命令行、代码和 Agent 概念的开发者、技术面试官与课程观众。桌面端是主场景，典型距离约 60–90cm；用户会阅读较长的 Markdown 回复、检查工具执行结果、切换历史会话，并在运行中插入 steer 或排队消息。移动端是辅助查看和轻量追问场景，不要求展示全部高级设置，但必须能进入会话历史、读完整时间线、展开工具步骤、发送或停止消息。界面既要在录屏或投屏时一眼看懂「Pi 正在做什么」，也要避免持续闪烁、重复警告和过多状态徽章干扰日常阅读。

## 共同内容与功能

每版必须包含：Pi Chat 品牌入口；一个当前会话标题；会话历史与搜索；连接状态；当前模型 Kimi K2.7 Code 与 thinking medium；一段用户任务；三步工具执行（write、edit、bash），其中包含成功和失败状态；一段 Pi 总结；底部输入工作台；图片输入、Steer/排队、停止或发送入口；一个 Harness/运行检查入口；仅出现一次的「本机可信环境，Bash 未隔离」安全状态。原型中的工具输出、时间、文件名和文案沿用现有演示数据，不增加虚构统计。

## 情感基调与视觉母题

关键词是：可信、专注、可追踪、有工程质感、不过度赛博。视觉母题是「一次任务由连续的可验证步骤组成」：会话是叙事主线，工具步骤是嵌入主线的执行证据，检查器是旁路仪表而不是第三个主角。三版都要避免紫色科技渐变、泛滥圆角卡片、装饰性图标、全屏霓虹和微缩标签。正文至少 14px，辅助标签至少 12px；正文对比度至少 4.5:1；桌面点击目标至少 36px，移动端至少 44px。

## 输出与响应式约束

每个方向交付一个无构建依赖的单文件 HTML，可直接 `file://` 打开。每版在 1440×900 和 390×844 下都有完整截图。桌面版必须展示侧栏、时间线、控制区和输入区之间的明确层级；移动版必须收起侧栏和次要模型控制，不允许简单把桌面三栏压窄。页面固定占满视口，时间线单独滚动，输入工作台稳定停靠在底部；不能出现横向滚动。每版至少具备可点击的侧栏/检查器切换、工具步骤展开、主题或布局状态切换之一。

## 三个独立方向

1. **Dark Editorial**：秒数轮盘得到网页风格 11。采用深色双色侧栏开发者作品集语法，但把主要阅读区处理成编辑式工作纸。重点是强排版、窄色谱、清晰的会话层级和单一运行强调色；不能退化为 GitHub 深蓝加霓虹。
2. **Warp Blocks**：现实标杆迁移自 Warp 官方 Terminal Blocks 概念。一个命令与其输出组成独立 Block，多个工具步骤形成连续 Run Group；重点是执行证据的可浏览、可折叠和状态汇总，整体骨架必须区别于普通聊天气泡。
3. **Rams Instrument Panel**：以 Dieter Rams 的「少而更好」与 Braun 仪器面板秩序为思维锚点。使用温暖中性色、精确分区、可读刻度与极少强调色；聊天居中，历史与检查器作为可开合仪表区，避免复古装饰模仿。

## 验收

三版布局骨架至少在导航位置、工具执行表达或控制区组织上有一项结构性差异；不是同一 DOM 只换色。无外部图片、无 Lorem Ipsum、无伪造性能数据。截图应直接支持横向比较，并在交付说明里写明各自的设计逻辑与「form 来自内容的哪里」。
